# Lemon EQ graph editor and dynamics

The EQ keeps Lemon branding, its plugin identity, its seven static band slots and all existing automation IDs. The interior is now a resizable graph with floating contextual controls. Existing saved projects keep their static response. Old dynamic controls retain their IDs; seventeen new controls are appended, making 47 dynamic parameters in addition to the original 36 parameters.

## Editing

Click the yellow curve or double-click the graph to create a band. A click elsewhere on an empty graph also creates on release; dragging empty space makes a selection rectangle. Click a band to show its compact card with a filter shape icon, frequency, gain, Q, power and headphones. Deep cuts leave their center clear. Open Band controls for the detailed knobs and dynamics in a drawer below the graph. Clicking empty space dismisses the selection. Q is the nominal bell quality converted from the existing octave bandwidth. The original fader bank has been removed to leave room for the graph.

Drag a node to change frequency and gain. Graph-point drags keep the pointer visible at its current position, including on release; precise knob and middle-button bandwidth drags retain relative adjustment. Ctrl-click toggles group selection; Shift-click extends selection between frequencies. Selected nodes move together; the main knobs also edit the group. Hold Shift during a drag for fine movement, or Alt to constrain node movement to one axis. The mouse wheel over nodes adjusts bandwidth (slope for pass filters); Ctrl-wheel adjusts gain, Alt-wheel adjusts dynamic range, and Ctrl+Alt-wheel adjusts gain and dynamic range inversely. Middle-drag a node adjusts bandwidth. Alt-click bypasses a band. A quick second click on a node starts dragging, including immediately after creation. Right-click a node and choose Type in value > Frequency, Gain or Q for precise entry; main knobs also retain their double-click entry. Right-click controls for the existing value/automation menu. The shape/slope/stereo labels open the band menu. Delete in the band right-click menu or contextual panel removes selected bands without renumbering automation, with Undo/Redo. Previous/next navigate by frequency. Click the headphones to audition the band’s frequency range, then drag the node to sweep it. Click again or clear the selection to stop. The drawer also has a hold-to-listen button. Audition ends when the editor closes and leaves saved EQ settings unchanged.

Undo/Redo buttons restore local editor sound edits, including group movements, wheel edits, creation and deletion. A/B stores and swaps the complete static, routing and dynamic configuration. It is local editor history, not a replacement for project history. Reset band resets its dynamics and spectral mode as well as gain/frequency/width. Seven slots remain; a full 24-band system, EQ Sketch, external sidechain, and complete Pro-Q feature parity are not included.

## Dynamics and spectral de-harsh

Click the labeled **Dynamic** button to enable dynamic EQ. It lights Lemon yellow and illuminates the outer Gain ring. Drag that ring to set dynamic range. Click Dynamic again to turn it off; the range is remembered for re-enabling during this editor session. Right-click a band for checked **Dynamic EQ** and **Spectral dynamics** options. Right-click empty graph space for **Add EQ band**, **Add dynamic band**, or **Add spectral band**. Negative range reduces, positive range boosts. The first range edit enables automatic dynamics. Expand the panel to switch to manual threshold, attack and release; collapse it to return to automatic dynamics. Threshold is dBFS and times are milliseconds. Conventional dynamic EQ uses a band-limited linked peak detector and smoothed minimum-phase bell/shelf filters. Auto uses a slow tracked signal threshold and frequency-dependent envelope times. Non-bell/shelf static types use a bell for their conventional dynamic stage.

The **Spectral** button enables dynamic EQ as needed and changes that band's dynamic stage to frequency-selective STFT processing. Turning Spectral off keeps ordinary dynamic EQ active; turning Dynamic off stops both modes, and their buttons and menu marks reflect the inactive state. The spectral mode setting is retained so re-enabling Dynamic can restore that mode. Each FFT bin is tested against nearby spectral energy and, in manual mode, its threshold. Band frequency/width delimit the weighted region. Stereo, Mid, Side, Left and Right detection and gain placement agree; untouched components reconstruct at unity. Automatic spectral mode uses local prominence with 6 ms attack and 100 ms release; manual mode uses the band's envelope controls.

De-harsh opens Amount, Threshold, Density, automatic mode and 3 dB/octave detector tilt. It operates across individual frequency bins in a tapered 1.5–14 kHz region. Amount is the maximum reduction per bin. Density controls local resonance selectivity; tilt increases high-frequency sensitivity. Automatic de-harsh uses local prominence independently of the manual level threshold. This replaces the previous twelve fixed dynamic bells. It is an original spectral algorithm, not FabFilter's implementation or a claim of sonic parity.

The yellow total curve includes the static response and current conventional/spectral gain changes. Conventional dynamics use the same filter response as the DSP. Spectral telemetry samples the live gain field at 256 log-spaced frequencies; a single combined display represents mixed stereo placements and is not a separate transfer function for every component. The colored envelope is the configured maximum range, not a measured instantaneous output spectrum. Detector meters show actual processed signal levels and reduction. Pre/Post/Off monitoring, analyzer precision/smoothing/range, histogram and heatmap remain available.

## Window and timing

Default size is 1000×620; resize independently from 640×420 up to 2400×1600. Windows frame edges/corner and the lower-right grip expose the diagonal resize cursor. The top-right interface-scale button cycles 100%, 125% and 150%; controls fit smaller windows automatically. Window dimensions and control scale are separate. Size lasts for the plugin instance and reopening its editor, not as a global saved preference. Other hosts must honor standard resize requests. Mac/Linux paths are implemented but have not been runtime tested here.

Spectral processing adds exactly 1024 samples below 88.2 kHz, 2048 at 88.2/96 kHz, or 4096 at 176.4/192 kHz to the static EQ's existing reported latency. Buffers/FFT storage are allocated when constructing the processor, not inside its spectral processing loop. Four-times-overlapped sqrt-Hann windows reconstruct the delayed dry signal at unity. Once engaged, the spectral stage retains its delay through bypass/release until processor reset; this avoids repeatedly changing alignment while editing. With all new controls at defaults, the original static audio path and latency are unchanged. Project saving, native rendering and plugin processing share the configuration and processor.

## Responsiveness and comparison polish — 6 November 2026

Static display responses are cached in a bounded, per-UI-thread eight-entry cache, keyed by band settings, mask, quality options, rate and plot width. Live reduction/spectral telemetry stays live. Dynamic display filters are designed once per band/paint instead of once per frequency sample. Windows parameter notifications coalesce to one queued wake-up; analyzer snapshots use try_lock so UI polling never waits for the audio callback. This is a targeted responsiveness improvement, not a promise about every system's perceived lag.

The compact glass panel has darker surfaces, full Attack/Release labels, a gain-reduction readout, and a highlighted Listen button while held. Listen temporarily auditions the selected frequency range and returns to the prior monitoring state on release. Existing top-row A > B and A / B buttons continue to store/swap static, dynamic and routing settings; A/B highlights the spare bank while it is active.

Level match is an optional, temporary RMS listening-comparison aid, off by default. It measures stereo pre/post energy, settles for 400ms, smooths detector energy over 400ms and compensation over 250ms, and bounds correction to +/-12dB. Near silence/startup/null outputs cannot trigger extreme boosts. It suspends during Listen and returns smoothly to unity when disabled or closed. It does not alter the output knob, parameter IDs or saved project/preset settings; it must be re-enabled after opening an editor. It affects the plugin's live audio output while active (including any render while the editor remains open), so disable it before exporting if the comparison compensation is unwanted. This is RMS level matching, not an integrated LUFS meter.

## Steady, time-based analyzer — 6 November 2026

Click the Speed button in the footer for the compact analyzer menu (also available by right-click): Speed, Resolution, Range, Tilt and Average. The main Options menu retains the same settings. New instances use Slow (40ms attack,450ms release time constants),2048-point resolution, existing90dB range and4.5dB/oct tilt. These are original Lemon display timings, not claims about FabFilter's internal implementation. Fastest/Fast/Medium/Slow/Slowest use attack0/10/25/40/65ms and release45/120/260/450/850ms time constants. Average uses the selected release constant in both directions.

Live analysis runs on an absolute30Hz deadline shared by Windows/Mac/Linux editor paths. Extra parameter wake-ups never trigger additional FFTs within that deadline; missed deadlines are skipped instead of queued. Spectrum measurements are separate from elapsed-time attack/release presentation; input events and point drags still repaint directly. Scratch input storage is reused; circular audio snapshots use two contiguous copies under try_lock. When a host stops supplying audio, the display falls to silence and stops requesting idle animation after settling. Invalid sample values cannot poison the display.

Resolution menu choices are1024/2048/4096/8192. Old saved indices0..3 continue to mean2048/4096/8192/16384; a loaded16384 choice appears as Legacy. New choices occupy indices4..7 in the existing visualization field, so old projects keep their FFT sizes and no audio/automation IDs change. Existing saved speed choices are retained, with the new consistent time-based smoothing. All changes are visualization-only; actual EQ processing and reported latency are unchanged.

## Continuous mouse refresh and spectrum drawing — 6 November 2026

Windows mouse/automation message handling now services a bounded input-frame deadline, polls current analyzer data and explicitly dispatches pending paint through UpdateWindow. Timer and ordinary paint messages can be delayed by input, so movement no longer depends on the mouse queue becoming idle to advance the spectrum. Relative knob drags receive the same refresh path. Plain hover no longer requests a full graph repaint for every coordinate change; hover-band transitions and actual edits still repaint. Generic Mac/Linux input paths also service polling/painting on the paced movement deadline rather than requiring Window::idle. No global event-loop, audio processing or saved-state changes.

Spectrum presentation uses narrow five-column power-domain smoothing with a peak floor (isolated peaks lose at most1.25dB), followed by bounded monotone cubic interpolation. This changes only the plotted spectrum: FFT measurements, dynamics detectors, EQ response curves, audio and saved parameters are untouched. A slightly clearer cool outline and subdued fill are drawn above the optional heatmap, keeping the curve legible. Interpolation has no local overshoot and remains clipped to the graph. The synthetic motion example checks rendering costs at100/150/200% DPI.

New regression drives2000consecutive actual Logic mouse moves with no Tick/idle/queued Paint events and the same input cadence used by the native path; analyzer measurements and rendered frames continue throughout. This deterministic input-path test plus native compilation does not claim physical Win32 mouse/paint dispatch was automated or tested. User hands-on verification remains.
